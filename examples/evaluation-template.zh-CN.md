# Agent 与 RAG 评估记录模板

[English](evaluation-template.md) | **简体中文** · [返回作品集](../README.zh-CN.md)

本文件用于展示**评估维度和方法**，并非某次测试已通过的报告。只有有真实运行证据时，才能填写结果并作为求职展示依据。

## 1. 测试范围

- 场景 / 用户问题：`[脱敏或合成样例]`
- 被测版本 / 环境：`[代码版本与配置]`
- 测试类型：脚本化确定性 / 浏览器 Mock / 真实浏览器 / 真实模型服务
- 预期允许的能力：`[公共证据 / 本地历史 / 澄清 / 禁止写入 / 其他]`
- 用户限制与系统政策：`[...]`

## 2. 语义理解与规划

- 用户目标、观察、歧义和关系是否被忠实保留：**是 / 部分 / 否**
- 是否考虑了必要的能力和义务：**是 / 部分 / 否**
- 对不明确或超出范围的请求是否明确处理：**是 / 否**
- 是否有无依据假设或遗漏意图：`[说明]`

## 3. 证据与检索

- 所选来源和范围：`[...]`
- 证据是否真正相关且足够：**是 / 部分 / 否**
- 遗漏证据、重复检索或无依据的主张：`[...]`
- 引用和检索单元标识是否在机制上有效：**是 / 否**

## 4. 工具与状态权限

- 计划调用与实际执行的工具：`[...]`
- 来源、身份、时间与访问授权是否正确：**是 / 否**
- 长期记录写入或状态修订是否明确获得授权：**是 / 否 / 不适用**
- 失败时是否保持受保护状态不变：**是 / 否 / 不适用**

## 5. 结果与局限

- JSON/Schema/结构化结果：`[...]`
- 工具执行结果：`[...]`
- **独立人工语义审核：** `[通过 / 失败 / 未审核]`
- 发现的问题与下一次验证：`[...]`

**原则：** 脚本化 PASS、JSON 正确和 HTTP 200 都不能证明模型完全正确地理解了用户，也不能单凭这些结果认定 Agent 已可安全发布。
