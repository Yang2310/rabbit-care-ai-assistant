# 公共 RAG：知识与检索架构

[English](rag-design.md) | **简体中文** · [系统架构](architecture.zh-CN.md)

## 不只是“把 PDF 分块放进向量库”

项目把**来源核验、可复用知识、检索表示和模型对证据的判断**拆分成相互独立的工程责任。

```text
Source Research / 已核验来源与证据范围
    ↓
Canonical Knowledge / 稳定知识段落与来源证明
    ↓
Retrieval Units / 面向检索的表示
    ↓
Embedding 供应商与 Chroma 索引
    ↓
候选召回 / 必要时补充检索
    ↓
证据选择 / 证据后的 Grounding 与回答判断
```

原始资料的主题名称和 Batch 位置**不适合**充当长期来源标识。知识标准化成果与研究流程元数据保持分离；后续可以在保留知识来源身份的基础上重新构造 Retrieval Units 或更换 Embedding。

## 关键技术决策

1. **先追踪来源，再做向量化：** 保留证据的来源和范围，不能仅凭向量相似度判断资料是否权威。
2. **先标准化知识，再建立索引：** 将资料整理成可复用段落，处理重叠、冲突和暂缓覆盖，而不是把所有原文 chunk 直接当成可回答的知识。
3. **检索表示与知识内容分离：** 面向 Embedding/Index 的 Retrieval Unit 是知识的下游表示，更换向量空间要进行隔离索引与验证。
4. **运行时检查证据质量：** 候选召回、查询修正、证据选择与最终回答分开；资料不足时应考虑追问或承认不足，而不是强行生成肯定答案。
5. **受控评估：** 用确定性样例检查检索轨迹、来源关联、候选选择、二次检索和索引隔离。模型真实的语义判断与医学适当性仍需独立人工审阅。

## 当前边界

私有仓库已经有实际知识资产和 RAG 评估基础设施，也实现了部分公共证据处理链路。**这不代表所有 Canonical 内容已被正式索引，也不表示默认检索路径全部切换完毕，或者真实模型助手已经通过最终验收。**

公开仓库不会包含私有来源资料、用户健康信息、密钥和原始向量索引。
